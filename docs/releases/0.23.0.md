## BREAKING

This release advances the minor version (Sickos is pre-1.0) and includes a breaking change. The Migration section below is copied verbatim, byte-for-byte, from the Dynamic Atmosphere GitHub release body.

## Migration

- Saved Dust, Ender Gas, Exhaust, Void Gas, and Slime atmosphere is dropped on load; affected chunks come back empty and refill from normal production.
- Existing `violence` server and client config resets to `voidGas` defaults; old `violence`/`violenceReachMultiplier`/`violenceOpticalDensity` values are not migrated.
- Forge config keeps an already-saved value when a default changes: a client with a saved `smokeOpticalDensity` (e.g. `4`, the old default) keeps rendering Smoke at that value. Delete `dynamicatmosphere-client.toml` or manually set `smokeOpticalDensity` to `2` to see the new look.
- Client and server must be upgraded together and match versions.
- Back up worlds before upgrading.

## Known issue

DA filed ATMO-21 after 0.20.0-alpha.1 published. In chunks saved by DA
0.19.x, the five resized materials (Dust, Ender Gas, Exhaust, Void Gas and
Slime) are skipped on load and their old data is preserved rather than
cleared, so they never reappear in already-explored areas and never refill.
Newly generated chunks are fine, and Vapor and Smoke are unaffected. A DA
0.20.1 patch is planned to actually clear the stale data. This means the
Migration section above, which says this data "is dropped on load", is
currently inaccurate for already-explored chunks; correcting that wording is
ATMO-21's job, not this release's.
